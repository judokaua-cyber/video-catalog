Резюме проєкту

Video Catalog — статичний веб-сайт для каталогізації YouTube-відео. Без серверної частини, без бази даних, без API-ключа YouTube. Усі дані — JSON-файли в теці data/. Хостинг — GitHub Pages.

Репозиторій github.com/judokaua-cyber/video-catalog
Live URL https://judokaua-cyber.github.io/video-catalog/
Гілка main
Локальна тека C:\Users\Kodak\PycharmProjects\video-catalog\
Власник judokaua-cyber <judoka.ua@gmail.com>

Стек технологій

  • HTML5 + CSS3 (без фреймворків)
  • Vanilla JavaScript (ES2020+), без збирача
  • GitHub Pages (хостинг, автодеплой із main)
  • GitHub REST API v3 (для запису з браузера)
  • File System Access API (Chrome/Edge, для запису в теку)
  • Python 3 (стандартна бібліотека, без залежностей) — для скриптів імпорту

Немає: Node.js, npm, webpack, React, Vue, будь-якого серверного коду. Усе працює як статичні файли.

albums.json

Масив об'єктів. Індекс усіх альбомів. Може бути великим (у цьому проєкті — 3.9 МБ через Base64-обкладинки). 

[
  {
    "id": "judo",
    "title": "Дзюдо",
    "description": "Техніка, кидки, захвати, рандорі",
    "cover": "data:image/webp;base64,UklGR...",
    "file": "judo.json",
    "sections": {
      "JUDO": {
        "description": "",
        "cover": "data:image/webp;base64,..."
      },
      "Kuzushi": {
        "description": "",
        "cover": ""
      }
    }
  }
]

Поля

id Унікальний ID. Генерується з назви (транслітерація + дефіси).
title Назва для людей.
description Короткий опис.
cover Base64 data URL обкладинки або "".
file Ім'я файлу з відео (у теці data/).
sections Об'єкт: ключ = назва розділу, значення = {description, cover}. Не впливає на перелік розділів — вони обчислюються з відео. Тут лише мета (обкладинка й опис).
Важливо sections не визначає, які розділи є. Розділи визначаються з поля section у файлі <album>.json. Якщо розділ є у відео, але немає в sections — розділ з'явиться без обкладинки й опису.

album.json

Масив відео одного альбому. Ім'я файлу — значення поля file з albums.json. 

[
  {
    "title": "Basic Ouchi gari",
    "section": "Зачеп",
    "subsection": "Зачеп ззовні",
    "url": "https://www.youtube.com/watch?v=e-CtiY2RLwA"
  },
  {
    "title": "Uchi Mata",
    "section": "Зачеп",
    "url": "https://www.youtube.com/watch?v=9bZkp7q19f0"
  }
]

Поля

title Обов'язкове. Назва відео.
section Обов'язкове. Назва розділу. Якщо порожнє — "Без розділу".
subsection Необов'язкове. Якщо немає — відео «без підрозділу». Не записується як "", просто не додається в об'єкт.
url Обов'язкове. YouTube-посилання у будь-якому форматі.

Правила даних

  1. Розділи та підрозділи не зберігаються окремо. Вони обчислюються з масиву відео при кожному завантаженні сторінки. Порожній розділ або підрозділ не існує.
  2. Дедуплікація. Ключ унікальності відео — пара (url, section, subsection). Одне й те саме відео може бути в різних розділах або підрозділах, але не двічі в одному.
  3. Нормалізація URL. Усі формати YouTube перетворюються на https://www.youtube.com/watch?v=ID під час парсингу. У файлі може бути будь-який формат — сайт нормалізує при відображенні.
  4. Порядок відео. Відео відображаються в тому порядку, у якому вони у файлі. Сортування не застосовується (крім підрозділів — за алфавітом).
  5. Регістр. Розділи й підрозділи чутливі до регістру: "Зачеп" і "зачеп" — різні.

github-api.js

Робота з GitHub REST API. Токен у localStorage під ключем GitHubAPI.token.

Константи

OWNER  = 'judokaua-cyber'
REPO   = 'video-catalog'
BRANCH = 'main'

Публічне API

hasToken()true/false.
getToken()Рядок токена.
setToken(token)Один аргумент. Зберігає з .trim().
forgetToken()Видалити з localStorage.
checkToken()GET /repos/OWNER/REPO. Повертає true/false. Ненадійний для публічних репо — може повернути true навіть із невалідним токеном, бо читання публічне.
readFile(path)GET /contents/<path>. Повертає {content, sha} або null при 404.
readFileViaFetch(path)Звичайний fetch /video-catalog/<path>. Працює для файлів > 1 МБ.
writeFile(path, content, message)PUT. Використовує readFile для отримання sha. Повертає {sha}.
Обмеження GitHub Contents API readFile не працює для файлів > 1 МБ — GitHub відмовляє або повертає обрізаний вміст. Для albums.json (3.9 МБ) тому використовується readFileViaFetch. Але writeFile усе одно викликає readFile для отримання sha — для файлів > 1 МБ це може зламати запис.

index.html

Головна сторінка. Каталог альбомів.

  • Рендерить картки альбомів через ContextCard.create().
  • Лічильники (розділів і відео) рахуються окремо через прямий fetch <album>.json з cache: 'no-store'.
  • ПКМ на картці альбому відкриває меню: Відкрити, Редагувати, Завантажити JSON, Додати посилання, Видалити.
Виправлення кешу У createAlbumCard() обов'язково fetch(DATA_BASE + album.file, { cache: 'no-store' }), інакше лічильники на головній показують старі цифри.

album.html + album.js

  • URL: album.html?id=<albumId>.
  • Завантажує albums.json → знаходить альбом → завантажує <album>.json.
  • Рендерить картки розділів через VideosStore.getSections().
  • Створення / редагування розділів: openSectionEditor() — кастомна модалка (обкладинка через Base64).
  • ПКМ на розділі: Відкрити, Редагувати, Додати відео, Видалити.
  • «＋ Новий розділ» — ContextCard.createNew().

section.html + section.js

Найскладніша сторінка. Три режими відображення:

  1. Огляд розділу (URL без sub): зверху папки підрозділів, знизу картки відео без підрозділу.

telegram_to_json.py

Масовий імпорт YouTube-посилань з експорту Telegram Desktop.

Потік

  1. Шукає найновішу підтеку ChatExport_* у C:\Users\Kodak\Downloads\Telegram Desktop\.
  2. Читає result.json, витягує URL з text і text_entities.
  3. Дедуплікує в межах експорту.
  4. Тягне назви через noembed.com (пауза 0.3 с).
  5. Очищає назви через clean_title().
  6. Питає альбом, розділ, підрозділ.
  7. Дедуплікує за (url, section, subsection).
  8. Дописує у data/<album>.json.
  9. Питає y/n на push. Якщо так — git add/commit/push.

Функція clean_title

Прибирає:

  • Емодзі-блоки: U+1F000–U+1FAFF, U+2600–U+27BF, U+2B00–U+2BFF, U+1F1E6–U+1F1FF (прапори), U+20E3.
  • Варіаційні селектори: U+FE00–U+FE0F.
  • Приховані: U+200B, U+200C, U+200D, U+2060, U+180E, U+FEFF, U+2028, U+2029, U+00A0.
  • Керуючі: U+0000–U+001F, U+007F.
  • Стискає подвійні пробіли.

Потік підрозділів

Створення підрозділу (через UI)

  1. ПКМ на картці відео → «📁 Перемістити в підгрупу».
  2. SubsectionPicker.open({section, currentSubsection, item, onDone}).
  3. Клік «➕ Новий підрозділ…» → showNewSubInput().
  4. Введення назви → state.targetSubsection = name.
  5. Крок 2: підтвердження → VideosStore.moveVideoToSubsection(index, name).
  6. dirty = true.
  7. onDone() → rebuildSectionVideos(), applyFilters(), showUnsavedHint().

Огляд розділу з підрозділами

  1. applyFilters() бачить, що currentSubsection === ''.
  2. Викликає renderOverview().
  3. VideosStore.getGroupedBySubsection(section) повертає {subsections, withoutSub}.
  4. Якщо subsections.length > 0 — малює зону #subsections-zone з картками-папками.
  5. Під папками — картки відео без підрозділу.

Перехід у підрозділ

  1. Клік на папці → URL section.html?id=…&name=…&sub=….
  2. init() читає sub → currentSubsection.
  3. applyMeta() додає хлібні крихти й замінює заголовок.
  4. applyFilters() фільтрує відео за subsection.

Групове переміщення

  1. Ctrl+Click на картці → selectedIndexes.add(index).
  2. Візуально — клас .is-selected (синя рамка).
  3. ПКМ на одній із виділених → пункт «📁 Перемістити вибране (N)».
  4. SubsectionPicker.open({section, items: [...]}).
  5. Вибір цільового підрозділу → for (item of items) moveVideoToSubsection(item.index, target).
  6. onDone() → перемалювання + showUnsavedHint().
Обмеження Ctrl+Click по активному iframe не спрацьовує (плеєр перехоплює клік). Для таких карток використовується кнопка □ — окремий елемент поза iframe.

Перевірка

GitHubAPI.hasToken()          // → true/false
await GitHubAPI.checkToken()  // → true/false (ненадійний для публічних)

Реальний тест

await GitHubAPI.writeFile('data/judo.json', '[]', 'Test')

Коди помилок GitHub

401 Bad credentialsТокен невалідний, прострочений або переданий неправильно.
403 ForbiddenТокен без scope repo, або репозиторій захищений.
404 Not FoundФайл або шлях не існує; або токен без доступу.
409 ConflictКонфлікт sha — файл змінився на GitHub між read і write.
422 UnprocessableНеправильний payload (наприклад, битий JSON).
Типова пастка setToken('github_token', 'ghp_...') — два аргументи. Функція бере лише перший. У localStorage запишеться рядок 'github_token', а не справжній токен. Потім hasToken() повертатиме true, а writeFile — 401. Причина довго неочевидна.

Відомі граблі

1. 404 при fetch, 200 при прямому запиті

Service Worker або HTTP-кеш можуть перехоплювати VideosStore.load() і віддавати стару відповідь. Перевірка: navigator.serviceWorker.getRegistrations() і caches.keys(). Рішення — Unregister + Clear storage.

2. Шлях без /video-catalog/

Якщо fetch використовує відносний шлях data/…, то на GitHub Pages він резолвиться від кореня домену (judokaua-cyber.github.io/data/…) — і дає 404. Треба абсолютний /video-catalog/data/….

3. Кеш лічильників на головній

Без cache: 'no-store' у fetch лічильники показують старі цифри після оновлення файлу альбому. Завжди додавати { cache: 'no-store' }.

4. GitHub Contents API > 1 МБ

readFile не працює для albums.json (3.9 МБ). Для читання — readFileViaFetch. Для запису потрібен інший підхід (Git Data API) або обмеження розміру.

5. Плутанина judo.json ↔ master.json

Якщо відкрити section.html?id=master і викликати вручну GitHubAPI.writeFile('data/judo.json', VideosStore.exportJson(), '…') — VideosStore містить master, і він запишеться в judo.json. Перезапис.

6. Різний регістр у назві розділу

Зачеп і зачеп — два різних розділи. Ключі (url, section, subsection) не збігаються. Завжди перевіряти регістр при імпорті з Telegram.

Кеш

Де кешується

  • HTTP-кеш браузера — cache: 'no-store' вирішує.
  • Service Worker — перевіряти navigator.serviceWorker.getRegistrations().
  • Cache Storage — caches.keys().
  • GitHub Pages CDN — затримка 30–60 с після push, іноді до 5 хв.

Як перевірити

// у консолі браузера
await fetch('/video-catalog/data/judo.json', {cache:'no-store'}).then(r => r.status)
navigator.serviceWorker.getRegistrations().then(rs => rs.length)
caches.keys().then(ks => console.log(ks))
localStorage.getItem('GitHubAPI.token')?.length

Як скинути

// у консолі
await navigator.serviceWorker.getRegistrations()
    .then(rs => Promise.all(rs.map(r => r.unregister())))
await caches.keys().then(ks => Promise.all(ks.map(k => caches.delete(k))))
location.reload(true)

Unicode-очищення

Назви з YouTube часто містять емодзі та невидимі Unicode-символи. У Python-скрипті вони прибираються функцією clean_title(). Вручну — через Notepad++ з регексом: 

[\x{200B}-\x{200D}\x{FEFF}\x{2028}\x{2029}\x{00A0}]

Замінити на порожнє. Увімкнути «Регулярні вирази» перед заміною.

Угоди коду

  • Мова інтерфейсу — українська.
  • Мова коду — англійська для змінних і функцій, українська для повідомлень користувачу й коментарів.
  • Модулі — IIFE, експорт через window.<Name>.
  • CSS-класи — kebab-case, з префіксами за модулем: cc- (context-card), md- (move-dup, subsection), sp- (subsection-picker).
  • Формат JSON — ensure_ascii=False, indent=2, LF-переведення рядків.
  • Коміти — англійською, коротко: Add …, Fix …, Update ….
  • Кирилиця в URL — завжди через encodeURIComponent.
  • HTML-атрибути — подвійні лапки.
  • Лапки в JSON — подвійні.

Публічні методи — тільки через явне повернення

return {
    load,
    getAll,
    // ...
};

Стан — модульний, не глобальний

Кожен модуль тримає свій приватний стан у замиканні IIFE. Глобальні змінні — тільки у section.js та подібних «сторінкових» скриптах (там це допустимо).
