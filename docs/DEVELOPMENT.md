# Посібник розробника

## Призначення проєкту

Video Catalog — це статичний клієнтський каталог YouTube-відео. Серверної
частини та етапу збірки немає: браузер безпосередньо завантажує HTML, CSS,
JavaScript і JSON-файли. Вміст каталогу зберігається у `data/`; файли відео
містять посилання та метадані, а не завантажені відеоматеріали.

Інтерфейс має три рівні:

1. `index.html` завантажує `data/albums.json` і відображає картки альбомів.
2. `album/album.html?id=<album-id>` завантажує `file` вибраного альбому та
   відображає його розділи.
3. `section/section.html?id=<album-id>&name=<section>&sub=<subsection>` фільтрує
   цей файл і відображає картки YouTube-відео.

`manual.html` — україномовний посібник користувача. Цей документ призначений
для супроводу проєкту та AI-агентів, що працюють із кодом.

## Структура репозиторію

| Шлях | Призначення |
| --- | --- |
| `index.html`, `index.js`, `index.css` | Каталог альбомів та інтерфейс редагування альбомів |
| `album/` | Каталог розділів та інтерфейс редагування розділів |
| `section/` | Каталог відео, пошук, перемикання вигляду та редагування відео |
| `js/store-albums.js` | Сховище альбомів у пам’яті, експорт і збереження `albums.json` |
| `js/store-videos.js` | Сховище відео у пам’яті, експорт і збереження JSON альбому |
| `js/file-storage.js` | File System Access API, GitHub і збереження через завантаження |
| `js/github-api.js` | Клієнт GitHub Contents API |
| `js/modal*.js`, `js/context-card.js` | Спільні діалоги, меню та сценарії переміщення/дублювання |
| `styles.css`, `css/` | Спільні стилі |
| `data/albums.json` | Індекс альбомів і метадані альбомів |
| `data/*.json` | Масиви відео, на які посилаються `albums.json[].file` |
| `manifest.json`, `sw.js`, `icons/` | Метадані PWA, service worker та іконки |

HTML-файли завантажують спільні скрипти перед скриптами конкретної сторінки.
Зберігайте цей порядок, додаючи модуль, який залежить від глобального об’єкта
спільного скрипту.

## Локальне налаштування та перевірки

Залежності для встановлення відсутні; налаштованих команд build, lint або test
немає. Використовуйте локальний HTTP-сервер: під час безпосереднього відкриття
HTML-файлу браузер не дозволяє завантажувати JSON-дані:

```text
python -m http.server 8000
```

Запускайте команду з кореня репозиторію, потім відкрийте
`http://localhost:8000/index.html`. Еквівалентні варіанти —
`python3 -m http.server 8000` і VS Code Live Server. Щоб зупинити сервер,
натисніть `Ctrl+C`.

Для змін лише в документації достатньо перевірити відображення Markdown і
наявність усіх згаданих шляхів. Для змін у застосунку перевірте в браузері всі
три сторінки та відповідний сценарій редагування/збереження.

## Потік даних і виконання

`AlbumsStore.load()` отримує `/video-catalog/data/albums.json`; запис кожного
альбому через властивість `file` вказує на інший JSON-файл. Сховища відео
зберігають розібрані дані в пам’яті та позначають їх як змінені після
редагування. Збереження перевіряє доступні способи в такому порядку:

1. File System Access API після вибору користувачем теки з правом запису.
2. GitHub Contents API, якщо вказано токен.
3. Завантаження файлу браузером як резервний варіант.

Поточні файли даних містять масиви. Записи альбомів мають поля `id`, `title`,
`description`, `cover`, `file` і `sections`. Записи відео мають поля `title`,
`section` і `url`; `subsection` є необов’язковим. Метадані розділів зберігаються
в `albums.json[].sections`.

## Конфігурація та облікові дані

Файлу `.env` або окремого файлу конфігурації під час виконання немає.
`js/github-api.js` визначає власника репозиторію (`judokaua-cyber`), репозиторій
(`video-catalog`) і гілку (`main`) як константи. Під час створення fork змінюйте
всі ці константи разом.

Токен GitHub вводиться в інтерфейсі та зберігається в `localStorage` під ключем
`GitHubAPI.token`; до репозиторію він не потрапляє. Стан теки File System Access
зберігається лише протягом сеансу, а назва останньої теки запам’ятовується під
ключем `FileStorage.lastFolderName`. Налаштування вигляду розділу (сітка/список)
зберігається під ключем `videoView`.

## Безпечне внесення змін

- Синхронізуйте імена файлів даних і посилання `albums.json[].file`.
- Зберігайте валідність JSON та наявні форми масивів/об’єктів.
- Під час перевірки fetch використовуйте локальний HTTP-сервер; після
  завантаження та збереження перевіряйте помилки в консолі браузера й повідомлення
  про стан.
- Зберігайте порядок залежностей скриптів у кожній HTML entry point.
- Враховуйте припущення щодо URL: застосунок використовує `/video-catalog/` у
  кількох fetch і в PWA manifest, а вкладені сторінки — відносні шляхи.
- Якщо змінюєте логіку збереження, окремо перевіряйте File System Access,
  GitHub-токен і резервне завантаження.
- Інструкції для користувачів зберігайте в `manual.html`; цей посібник оновлюйте
  лише щодо архітектури, команд або безпечної роботи зі змінами.
