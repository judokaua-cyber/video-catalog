Що це таке

Це статичний веб-сайт для каталогізації YouTube-відео. Він не потребує серверної частини, бази даних, API-ключа YouTube чи щомісячної плати. Уся інформація зберігається у звичайних JSON-файлах у теці data/, а сам сайт складається лише з HTML, CSS і трохи JavaScript.

Каталог можна розмістити безкоштовно на GitHub Pages, Cloudflare Pages, Netlify — де завгодно.

Ключова ідея Відео не завантажуються на сайт. Зберігаються лише посилання на YouTube. Плеєр вбудовується на сторінку динамічно, коли ви натискаєте на прев'ю.

Структура проєкту

WEB_project/ │ ├── index.html ← Головна (каталог альбомів) ├── index.js ← Логіка головної ├── index.css ← Стилі головної ├── styles.css ← Базові стилі (спільні) ├── manual.html ← Цей посібник │ ├── album/ │ ├── album.html ← Каталог розділів одного альбому │ ├── album.js │ └── album.css │ ├── section/ │ ├── section.html ← Каталог відео одного розділу │ ├── section.js │ └── section.css │ ├── css/ ← Спільні стилі │ ├── context-card.css (картки + ПКМ-меню) │ └── modal.css (модальні вікна) │ ├── js/ ← Спільні модулі JS │ ├── store-albums.js (робота з albums.json) │ ├── store-videos.js (робота з albumN.json) │ ├── modal.js (модальні вікна) │ └── context-card.js (картки + ПКМ) │ └── data/ ← ДАНІ (усе, що ви редагуєте) ├── albums.json ← Індекс усіх альбомів ├── album1.json ← Відео альбому 1 ├── album2.json ← Відео альбому 2 └── album3.json ← Відео альбому 3
Не плутайте albums.json (з літерою s на кінці) — це індекс усіх альбомів. А album1.json, album2.json (без s) — це відео конкретного альбому. Це різні файли.

Як запустити локально

Просто відкрити index.html у браузері не вийде — браузер блокує читання локальних JSON-файлів із міркувань безпеки. Потрібен локальний веб-сервер.

Варіант 1. Python (найшвидший)

Відкрийте PowerShell. Виконайте три команди:

H:
cd \WEB_project
python3 -m http.server 8000

Побачите рядок Serving HTTP on :: port 8000 .... Це означає, що сервер працює. Відкрийте у браузері: 

http://localhost:8000/
Як зупинити сервер Поверніться у вікно PowerShell, натисніть Ctrl+C.

Варіант 2. VS Code Live Server

  1. Встановіть розширення Live Server у VS Code.
  2. Відкрийте теку WEB_project.
  3. Права кнопка на index.html → Open with Live Server.

Якщо python3 не знайдено

Спробуйте python замість python3:

python -m http.server 8000

Якщо й це не працює — Python не встановлено. Завантажте з python.org, під час встановлення обов'язково позначте "Add Python to PATH".

Навігація

Сайт має три рівні. Перехід — зліва направо, кліком лівою кнопкою миші.

┌─────────────────────────────────────┐ │ Головна (index.html) │ │ 3 картки альбомів + "Новий альбом" │ └──────────────┬──────────────────────┘ │ ЛКМ на картці ▼ ┌─────────────────────────────────────┐ │ Альбом (album.html?id=album1) │ │ Картки розділів + "Новий розділ" │ └──────────────┬──────────────────────┘ │ ЛКМ на картці ▼ ┌─────────────────────────────────────┐ │ Розділ (section.html?id=…&name=…) │ │ Картки відео │ └──────────────┬──────────────────────┘ │ ЛКМ на ▶ ▼ YouTube плеєр у картці

Кожна сторінка має хлібні крихти вгорі — щоб повернутися на рівень вище одним кліком.

Редагування альбомів

На головній сторінці є картки альбомів. З ними можна робити таке:

Створити новий альбом

  1. Клік на картку "＋ Новий альбом".
  2. Заповніть Назву, Опис, оберіть обкладинку (необов'язково).
  3. Натисніть Створити.
  4. Погодьтеся на створення файлу даних (див. нижче).
Автоматичні ID Назва альбому автоматично перетворюється на ID:
«Техніка у стійці» → tekhnika-u-stiytsi
«Ката 2024» → kata-2024
Латиниця, цифри, дефіси — решта символів прибирається.

Редагувати альбом

ПКМ на картці → Редагувати альбом. У модалці змініть назву, опис або обкладинку → Зберегти.

Обкладинка альбому

У модалці редагування — кнопка "📁 Обрати файл…". Виберіть зображення з диска. Воно автоматично перетвориться на Base64 і збережеться прямо в albums.json.

Розмір обкладинки Рекомендовано до 300 КБ. Якщо більше — сайт попередить. Base64 збільшує розмір файлу на ~30%. Стискайте картинки перед завантаженням (наприклад, через squoosh.app).

Видалити альбом

ПКМ на картці → Видалити альбом → підтвердити. Альбом зникне з albums.json, але файл albumN.json залишиться на диску — його треба видалити вручну, якщо більше не потрібен.

Редагування розділів

На сторінці альбому — картки розділів. Дії ті самі, що й для альбомів.

Створити новий розділ

  1. На сторінці альбому клік на "＋ Новий розділ".
  2. Введіть назву (наприклад, JUDO), опис.
  3. Натисніть Створити.
  4. Сайт запитає: "Додати відео зараз?". Погодьтеся або відмовтеся.
Порожній розділ невидимий Розділ з'являється у списку лише після того, як у нього додано хоча б одне відео. Це особливість архітектури: розділи обчислюються з наявних відео.

Додати відео в розділ

ПКМ на картці розділу → Додати відео. Вставте одне або кілька посилань — по одному в рядку, або всі підряд.

Редагування відео

На сторінці розділу — картки відео. ПКМ на картці відкриває меню:

✏️ Редагувати
🔀 Переміщення / Дублювання
🗑️ Видалити відео

Редагувати

Відкриває модалку з трьома полями:

  • Назва — те, що видно під прев'ю.
  • URL — посилання на YouTube у будь-якому форматі.
  • Розділ — випадаючий список. Зміна переміщує відео в інший розділ.

Переміщення / Дублювання

Відкриває модалку з сіткою всіх розділів альбому. Спочатку треба обрати цільовий розділ (крок 1), потім — обрати дію (крок 2):

  • 🔀 Перемістити — відео зникає з поточного розділу і з'являється в цільовому. Недоступно, якщо цільовий = поточний.
  • 📋 Дублювати — створюється копія відео з назвою «Назва (копія)» у цільовому розділі. Оригінал залишається на місці.
Навігація в модалці Хлібні крихти вгорі модалки показують шлях: Альбом › Цільовий розділ. Клік на назву альбому повертає до вибору розділу.

Видалити відео

Запитує підтвердження і видаляє відео з albumN.json.

Контекстне меню (ПКМ)

Права кнопка миші на будь-якій картці відкриває контекстне меню з діями. Це основний спосіб редагування.

Де Дії в ПКМ
Картка альбому
(на головній)		 📂 Відкрити · ✏️ Редагувати альбом · 📥 Завантажити JSON · 🔗 Додати посилання · 🗑️ Видалити альбом
Картка розділу
(на сторінці альбому)		 📂 Відкрити · ✏️ Редагувати розділ · 🔗 Додати відео · 🗑️ Видалити розділ
Картка відео
(на сторінці розділу)		 ✏️ Редагувати · 🔀 Переміщення / Дублювання · 🗑️ Видалити відео

Меню закривається:

  • Кліком на будь-який пункт.
  • Кліком деінде на сторінці.
  • Клавішею Esc.

Файли даних

Уся інформація каталогу живе у теці data/. Два типи файлів:

albums.json — індекс альбомів

Один файл. Містить масив записів про всі альбоми: ID, назва, опис, обкладинка, ім'я файлу з відео.

albumN.json — відео одного альбому

Один файл на кожен альбом. Містить масив відео: назва, розділ, URL.

Формат JSON

albums.json

[
  {
    "id": "judo-basics",
    "title": "JUDO Basics",
    "description": "Основи дзюдо",
    "cover": "data:image/jpeg;base64,/9j/4AAQ...",
    "file": "judo-basics.json",
    "sections": {
      "Кидки": {
        "description": "Техніка кидків",
        "cover": ""
      }
    }
  }
]

albumN.json (наприклад, judo-basics.json)

[
  {
    "title": "Osoto Gari",
    "section": "Кидки",
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
  },
  {
    "title": "Uchi Mata",
    "section": "Кидки",
    "url": "https://youtu.be/9bZkp7q19f0"
  }
]
URL — у будь-якому форматі Сайт розуміє всі формати YouTube:
  • https://youtu.be/ID
  • https://www.youtube.com/watch?v=ID
  • https://www.youtube.com/shorts/ID
  • https://www.youtube.com/embed/ID
  • Просто ID (11 символів)

Збереження змін

Зміни, зроблені на сайті, спочатку живуть тільки у пам'яті браузера. Щоб вони потрапили у файл на диску, треба натиснути кнопку «💾 Зберегти» в банері, який з'являється внизу екрана. Спосіб збереження залежить від браузера.

Спосіб 1. File System Access API (Chrome, Edge, Opera)

Це найзручніший режим. Файл зберігається прямо у вашу теку data/, без завантажень у Downloads.

  1. Ви щось змінюєте на сайті (додаєте відео, редагуєте назву…).
  2. Внизу з'являється банер:
    ⚠️ Є незбережені зміни [💾 Зберегти album1.json]
  3. Натискаєте кнопку. Першого разу браузер попросить вибрати теку — вкажіть H:\WEB_project\data\ і натисніть «Зберегти доступ».
  4. Усі наступні збереження летять у цю саму теку автоматично.
  5. Оновлюєте сторінку — зміни закріпилися.
Дозвіл скидається при перезапуску браузера Якщо ви повністю закриєте Chrome і відкриєте знову — треба буде ще раз обрати теку (один клік). Це обмеження браузера, а не сайту.
Важливо: обирайте саме data/ Якщо виберете H:\WEB_project\ замість H:\WEB_project\data\ — файли потраплять у корінь проєкту, і сайт їх не знайде. Будьте уважні.

Спосіб 2. Завантаження в Downloads (Firefox, Safari)

Якщо браузер не підтримує File System Access API — файл завантажується у теку Downloads, як звичайний файл.

  1. Ви щось змінюєте на сайті.
  2. Внизу з'являється банер:
    ⚠️ Є незбережені зміни [💾 Зберегти album1.json]
  3. Натискаєте — файл з'являється в C:\Users\ВашеІм'я\Downloads\.
  4. Вручну копіюєте його в H:\WEB_project\data\, замінюючи старий.
  5. Оновлюєте сторінку — зміни закріпилися.
Як дізнатись, який спосіб використано Після збереження сайт показує повідомлення внизу сторінки:
  • «✅ Збережено у вибрану теку» — Спосіб 1 (File System Access).
  • «✅ Завантажено в Downloads» — Спосіб 2 (завантаження файлу).
Чому браузер не пише файли сам Без явного дозволу користувача жоден сайт не може записувати файли на диск — це фундаментальна вимога безпеки вебу. File System Access API працює тільки після того, як ви свідомо вибрали теку й натиснули «Зберегти доступ».

Публікація на GitHub Pages

Крок 1. Створіть репозиторій

  1. Зареєструйтесь на github.com, якщо ще немає акаунта.
  2. Створіть новий репозиторій: New repository.
  3. Назва — будь-яка (наприклад, video-catalog).
  4. Поставте галочку Public.
  5. Не додавайте README / .gitignore — просто Create.

Крок 2. Завантажте файли

Найпростіше — через веб-інтерфейс GitHub:

  1. У порожньому репозиторії натисніть "uploading an existing file".
  2. Перетягніть усі файли й теки з H:\WEB_project\.
  3. Внизу натисніть Commit changes.
Не забудьте про теку data/ GitHub Pages має бачити усі JSON-файли. Перевірте, що data/albums.json, data/album1.json тощо справді завантажені. Інакше сайт покаже помилку.

Крок 3. Увімкніть GitHub Pages

  1. У репозиторії — вкладка Settings.
  2. Ліве меню — Pages.
  3. У розділі Source — виберіть Deploy from a branch.
  4. Branch: main, folder: / (root).
  5. Натисніть Save.

Через 1–2 хвилини сайт буде доступний за адресою:

https://ваш-логін.github.io/video-catalog/

Як оновлювати каталог

Каталог можна поповнювати трьома способами:

  1. Масовий імпорт із Zoho Notebook — Python-скрипт читає експорт HTML і створює файли data/*.json.
  2. Масовий імпорт із Telegram — окремий скрипт для іншого формату (розглядається нижче).
  3. Ручне додавання через ПКМ-меню прямо на сайті (для поодиноких відео).

Нижче описано перший спосіб — масовий імпорт із Zoho. Він актуальний, якщо у вас накопичено багато карток у Zoho Notebook і треба перенести їх у каталог.

Частина 1. Масовий імпорт із Zoho

Коли це потрібно Якщо ви назбирали нові картки в Zoho Notebook і хочете перенести їх у каталог. Скрипт zoho_to_json.py прочитає усі HTML-файли зі своєї теки, згрупує за розділами й альбомами та створить готові JSON у теці data/.

Що потрібно підготувати

У теці H:\WEB_project\Zoho_convert\ мають лежати:

Zoho_convert/ ├── zoho_to_json.py ← скрипт (не чіпаємо) ├── zoho_export/ ← HTML-файли, експортовані з Zoho │ ├── *.html │ └── PrivateCovers/ ← заставки розділів (експорт Zoho) ├── covers/ ← заставки розділів (копії, готові до використання) └── tytul/ ← обкладинки альбомів ├── judo.png ├── master.png └── pobut.png
Експорт із Zoho HTML-файли експортуються вручну з Zoho Notebook: виділіть картки → Експорт → HTML. Потім покладіть їх у Zoho_convert/zoho_export/. Так само — заставки розділів у PrivateCovers/.

Структура маппінгу: розділ → альбом

Zoho не має поняття «альбом» — тільки «розділ» (notebook). Щоб розділи потрапили у правильні альбоми, у скрипті є таблиця ALBUM_MAPPING: 

ALBUM_MAPPING = {
    "JUDO": "judo",
    "Kuzushi": "judo",
    "Больові": "judo",
    ...
    "a_1 Верстат": "master",
    ...
    "Їжа": "pobut",
}

Ліворуч — назва розділу в Zoho, праворуч — ID альбому (judo, master, pobut).

Якщо з'явився новий розділ Після запуску скрипт напише у звіті: «Розділів не знайдено в ALBUM_MAPPING». Відкрийте zoho_to_json.py, додайте потрібний рядок у таблицю, збережіть і запустіть знову.

Запуск скрипта

Відкрийте PowerShell і виконайте:

H:
cd \WEB_project\Zoho_convert
python zoho_to_json.py

Скрипт виведе щось таке:

════════════════════════════════════════════════════════════ Zoho -> JSON конвертер ════════════════════════════════════════════════════════════ Вхід: H:\WEB_project\Zoho_convert\zoho_export Вихід: H:\WEB_project\data 📄 Знайдено HTML-файлів: 1553 Карток з YouTube-посиланням: 1501 Карток без YouTube: 51 (пропущено) Невалідних HTML: 1 📝 Формування JSON... ✓ judo: обкладинка judo.png ✓ judo.json: 22 розділів, 380 відео ✓ master: обкладинка master.png ✓ master.json: 10 розділів, 1119 відео ✓ pobut: обкладинка pobut.png ✓ pobut.json: 1 розділів, 2 відео ✓ albums.json: 3 альбомів ════════════════════════════════════════════════════════════ ✅ Готово! ════════════════════════════════════════════════════════════

Що саме створює скрипт

У теці H:\WEB_project\data\ оновлюються або створюються:

  • albums.json — індекс альбомів (з обкладинками Base64 із теки tytul/).
  • judo.json — відео альбому «Дзюдо».
  • master.json — відео альбому «Майстерня».
  • pobut.json — відео альбому «Побут».
Старі файли Скрипт не видаляє сторонні файли з data/. Якщо там залишились тестові album1.json, album2.json тощо — їх треба прибрати вручну. Вони не заважатимуть роботі, але й не будуть використовуватись каталогом.

Перевірка результату

  1. Відкрийте H:\WEB_project\data\ у Проводнику. Переконайтесь, що albums.json та три judo.json / master.json / pobut.json мають щойно оновлений час зміни.
  2. Запустіть локальний сервер і відкрийте каталог (див. розділ «Як запустити локально»).
  3. На головній сторінці побачите три альбоми з обкладинками та правильними лічильниками.
  4. Усередині альбомів — розділи з заставками. Відео відтворюються при кліку на ▶.
Готово Після запуску скрипта каталог оновлено. Можете закрити Zoho Notebook — усі дані вже в JSON-файлах.

Можливі проблеми

Що бачите Що робити
«Не знайдено теку zoho_export» Перевірте, що тека справді називається zoho_export і лежить поруч зі скриптом.
«Розділів не знайдено в ALBUM_MAPPING» Відкрийте zoho_to_json.py, знайдіть ALBUM_MAPPING, додайте рядок "Назва розділу": "judo" (або інший альбом). Збережіть — запустіть знову.
Багато карток «без YouTube» Перевірте, чи у картках справді є посилання на YouTube. Якщо так, але скрипт їх не бачить — покажіть приклад HTML, треба буде підправити регулярний вираз.
Обкладинка альбому не з'явилась Перевірте, що у tytul/ є файл judo.png (або відповідний для іншого альбому). Ім'я файлу має співпадати з полем cover_file у скрипті.
Розділ без заставки Нормально. Якщо для розділу немає PNG у covers/ — у каталозі покажеться кольорова плитка з першою літерою. Можна додати PNG вручну і запустити скрипт знову.

Частина 2. Масовий імпорт із Telegram

У розробці Цей розділ буде додано пізніше. Telegram-експорт має інший формат, тому для нього знадобиться окремий скрипт.

Частина 3. Ручне додавання

Для поодиноких відео не потрібен скрипт. Просто відкрийте потрібний розділ на сайті та використайте ПКМ → Додати відео. Детально — у розділі «Редагування розділів».
