Коли це потрібно

Іноді зручніше відредагувати JSON вручну — у PyCharm або Notepad++ — ніж клацати ПКМ на сайті. Наприклад:

  • Треба масово замінити щось у багатьох записах (наприклад, виправити одруківку в назві розділу).
  • Треба додати кілька відео одночасно, і ви вже маєте готовий список.
  • Треба змінити порядок відео, щоб певні йшли першими.
  • Ви випадково зіпсували запис, і треба виправити вручну.
Це стосується файлів альбомів Приклади: data/judo.json, data/master.json, data/pobut.json. Це не стосується albums.json — його краще редагувати через сайт, бо там Base64-обкладинки (легко щось зламати).

Структура файлів

Усі файли живуть у репозиторії на ПК: 

C:\Users\Kodak\PycharmProjects\video-catalog\
├── data\
│   ├── albums.json          ← індекс альбомів (не чіпайте вручну)
│   ├── judo.json            ← альбом «Дзюдо»    ← редагуємо
│   ├── master.json          ← альбом «Майстерня» ← редагуємо
│   └── pobut.json           ← альбом «Побут»     ← редагуємо

Запис відео має такий вигляд:

{
  "title": "Basic Ouchi gari",
  "section": "Зачеп",
  "subsection": "Зачеп ззовні",
  "url": "https://www.youtube.com/watch?v=e-CtiY2RLwA"
}

Поле subsection — необов'язкове. Якщо його немає, відео вважається «без підрозділу». Поле section — обов'язкове.

1. Відкрити і відредагувати

  1. Відкрийте PyCharm. У лівому дереві проєкту знайдіть data/ → потрібний файл, наприклад judo.json.
  2. Двічі клікніть на файл — він відкриється в редакторі.
  3. Внесіть зміни. Найчастіші операції:
    • Додати відео — скопіюйте попередній блок { ... }, вставте після нього, змініть title, section, url.
    • Змінити розділ — знайдіть "section": "Старе" і замініть на "section": "Нове".
    • Видалити відео — виділіть весь блок { ... }, разом із комою — і видаліть.
    • Змінити порядок — виріжте блок і вставте в інше місце.
  4. Збережіть файл: Ctrl+S.
Увага на коми й дужки JSON дуже чутливий до дрібниць:
  • Між об'єктами обов'язкова кома: }, {.
  • Після останнього об'єкта кома не потрібна.
  • Усі ключі й рядки — у подвійних лапках "title", не 'title' і не title.
  • Кожна { має свою }.
  • Файл закінчується на ].

2. Перевірити JSON

Перед тим, як комітити, переконайтесь, що JSON валідний. Інакше сайт зламається.

Спосіб А — PyCharm автоматично

PyCharm підсвічує синтаксичні помилки червоним. Якщо бачите червоне підкреслення в файлі — щось не так. Наведіть курсор на підкреслене — PyCharm скаже, що саме.

Спосіб Б — онлайн-валідатор

Відкрийте jsonlint.com → вставте весь вміст файлу → Validate JSON. Якщо валідатор каже Valid JSON — усе гаразд.

Спосіб В — консоль браузера

Якщо файл уже на GitHub, відкрийте каталог у браузері й у консолі (F12) перевірте, чи немає помилок парсингу. Сторінка альбому з порожнім списком — явна ознака, що JSON побитий.

3. Стягнути з GitHub

Обов'язковий крок перед пушем. Якщо ви паралельно щось редагували через браузер GitHub (або інший ПК), ваш локальний репозиторій уже відстає. Без pull пуш буде відхилений.

У Terminal PyCharm (внизу вікна, вкладка «Terminal»):

git pull

Що побачите:

ПовідомленняЩо робити
Already up to date. Нічого нового на GitHub. Можна переходити до коміту.
Fast-forward або Merge made by… Підтягнулось усе успішно. Переходьте далі.
CONFLICT … Дивіться розділ Конфлікт при pull нижче.

4. Закомітити

Тепер треба зафіксувати ваші зміни в локальній історії git.

Через GUI PyCharm (простіше)

  1. У лівій панелі відкрийте вкладку Commit (іконка з галочкою).
  2. У списку змінених файлів має бути ваш judo.json. Поставте біля нього галочку.
  3. Введіть повідомлення коміту, наприклад: Оновив розділ Зачеп у judo.json.
  4. Натисніть кнопку Commit and Push… (не просто Commit).

Через Terminal

git add data/judo.json git commit -m "Оновив розділ Зачеп у judo.json" git push
Що робить кожна команда
  • git add — додає файл у «чернетку» наступного коміту.
  • git commit — фіксує зміни в локальній історії.
  • git push — відправляє коміти на GitHub.

5. Запушити

Якщо у кроці 4 ви обрали Commit and Push — пуш уже відбувся. Якщо ви робили лише Commit, треба зробити пуш окремо:

git push

Успішний пуш виглядає так:

Enumerating objects: 5, done. Counting objects: 100% (5/5), done. ... To https://github.com/judokaua-cyber/video-catalog.git abc1234..def5678 main -> main

Рядок abc1234..def5678 main -> main означає, що коміти пішли на GitHub.

6. Перевірити на сайті

  1. Зачекайте 30–60 секунд. GitHub Pages автоматично перебудовує сайт після кожного коміту.
  2. Відкрийте каталог: https://judokaua-cyber.github.io/video-catalog/
  3. Натисніть Ctrl+Shift+R — це жорстке оновлення, яке очищає кеш браузера. Без цього ви можете бачити стару версію.
  4. Зайдіть у відповідний альбом і розділ. Перевірте, чи є ваші зміни.
Готово Якщо зміни видно — усе спрацювало. Якщо ні — зачекайте ще 30 секунд і оновіть з очищенням кешу.

Проблема: конфлікт при pull

Якщо git pull показав CONFLICT (content): Merge conflict in data/judo.json — це означає, що той самий файл змінено і локально, і на GitHub. Git не знає, яку версію залишити.

Що робити

  1. У лівому дереві PyCharm знайдіть data/judo.json — він підсвічений червоним.
  2. Права кнопка на файлі → Git → Resolve Conflicts…
  3. Відкриється редактор із трьома колонками:
    • ліва — ваша локальна версія,
    • права — версія з GitHub,
    • посередині — результат, який піде в коміт.
  4. Виберіть, що залишити. Якщо треба обидві версії — приберіть маркери <<<<<<<, =======, >>>>>>> і залиште обидва блоки.
  5. Натисніть Apply.
  6. Поверніться в Terminal і виконайте:
    git add data/judo.json git commit -m "Merge: resolve conflict" git push
Як уникнути конфліктів Перед тим, як редагувати файл у PyCharm, зробіть git pull. Це підтягне свіжу версію з GitHub, і ви працюватимете з нею.

Проблема: помилка в JSON

Якщо ви забули кому або закрили не ту дужку, сайт може показати порожній альбом або взагалі не завантажитись.

Ознаки

  • Сторінка альбому відкривається, але показує 0 розділів.
  • У консолі браузера (F12) — червона помилка SyntaxError або Unexpected token.
  • PyCharm підсвічує рядок червоним.

Що робити

  1. Відкрийте файл у PyCharm. Знайдіть червоне підкреслення.
  2. Перевірте найчастіші помилки:
    • пропущена кома між }, {;
    • зайва кома після останнього об'єкта;
    • одна { без парної };
    • використані одинарні лапки 'title' замість подвійних "title".
  3. Виправте помилку, збережіть файл.
  4. Якщо не можете знайти — відкрийте файл у jsonlint.com, він покаже номер рядка з помилкою.

Як відкотити зміни

Якщо зіпсували файл і хочете повернути версію з GitHub:

git checkout data/judo.json

Увага: це видалить усі ваші локальні зміни в цьому файлі й поверне версію з останнього коміту.

Проблема: Push rejected

Помилка:

! [rejected] main -> main (fetch first) error: failed to push some refs

Це означає, що на GitHub є коміти, яких немає у вас локально. Ви пушнете поверх них — git відмовляється.

Що робити

  1. Спочатку підтягніть з GitHub:
    git pull
  2. Якщо конфліктів немає — повторіть:
    git push
  3. Якщо є конфлікт — дивіться розділ Конфлікт при pull.

Шпаргалка команд

КомандаЩо робить
git pull Стягнути свіжі зміни з GitHub. Робіть перед кожним редагуванням.
git status Показати, які файли змінені локально.
git diff data/judo.json Показати, що саме змінилось у файлі.
git add data/judo.json Підготувати файл до коміту.
git commit -m "…" Закомітити зміни з повідомленням.
git push Відправити коміти на GitHub.
git log --oneline -5 Показати останні 5 комітів.
git checkout data/judo.json Скасувати всі локальні зміни у файлі, повернути версію з останнього коміту.
Не використовуйте без розуміння
  • git reset --hard — видалить усі локальні зміни в усьому проєкті.
  • git push --force — перезапише історію на GitHub. Використовуйте лише якщо точно знаєте, що робите.
  • git clean -fd — видалить файли, яких немає в git-історії.
Правильний цикл роботи
  1. git pull — стягнути свіже.
  2. Редагувати файл у PyCharm.
  3. Ctrl+S — зберегти.
  4. Перевірити JSON-валідатором.
  5. git add + git commit + git push.
  6. Через 30 секунд — перевірити на сайті з Ctrl+Shift+R.
